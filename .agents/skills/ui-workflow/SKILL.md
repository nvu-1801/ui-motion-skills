# ui-workflow

1. Read repository instructions, package and lockfile, target routes, existing tokens and UI primitives. Identify the primary audience, task and acceptance criteria.
2. Trace the real workflow before changing presentation. Record route, CTA destination, form validation, permissions, locale and loading/empty/error behavior where applicable.
3. For UI implementation, find the existing component/variant/token source first; use ui-system-reuse only when discovery, consistency or duplication needs guidance. Pick one visual direction and one primary action per section. Load ui-design only for visual direction decisions and ui-components only when implementation guidance is needed. For a changed landing or lead contract, use landing-business-rules when available. Do not load all UI skills just because they are installed. Add scroll or 3D only when it supports a specific content beat.
4. Implement through the existing route and data flow. Verify the changed workflow and record observed checks and screenshots.
