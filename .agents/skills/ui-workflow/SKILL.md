# ui-workflow

1. Read repository instructions, package and lockfile, target routes, existing tokens and UI primitives. Identify the primary audience, task and acceptance criteria.
2. Trace the real workflow before changing presentation. Record route, CTA destination, form validation, permissions, locale and loading/empty/error behavior where applicable.
3. Pick one visual direction and one primary action per section. Use the installed design and component skills when present. For a landing page or lead flow, use landing-business-rules when available. Add scroll or 3D only when it supports a specific content beat.
4. Implement through the existing route and data flow. Verify the changed workflow and record observed checks and screenshots.
